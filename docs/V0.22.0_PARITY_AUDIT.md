### Routage des modèles

Principal : `openai-codex/gpt-6.1-sol`, OpenAI Codex OAuth. AGENTS global fourni au contexte et RULES global lu : même consigne. Lecture effective des réglages : overrides d'agents vides, sélection de modèle par appel désactivée, rôle `default` configuré sur un autre fournisseur et fallbacks activés. **Aucune preuve d'un routage résolu conforme pour un enfant : zéro sous-agent.** Aucun paramètre global changé. Le niveau demandé est xhigh ; le réglage global `auto` n'atteste pas l'effort exact de chaque requête.

Incident de routage à conserver : le premier `find` a tenté25 jugements `openrouter/typesafe/jev-1.14`, tous échoués402/0token, sans résultat de modèle. L'outil a été exclu immédiatement, incident signalé ; suite uniquement par lectures, recherches textuelles et commandes locales/API GitHub. Ne pas réutiliser `find`, `web_search` à modèle ou délégation indirecte sans preuve du fournisseur. DeepSeek ultérieur = session principale distincte expressément autorisée, jamais fallback de cette session.

## 4. Architecture cible et risques à verrouiller

Conserver le chemin B5 : **owner Rust/tray permanent → bundle Flutter de confiance possédé → pipes anonymes privés hérités → demandes typées Rust**. Aucun serveur réseau, shell ou token en argv. Windows : enfant suspendu contenu dans Job Object kill-on-close et handles allowlistés avant exécution. Unix : racines/payloads épinglés, modes/owner/ACL/liens vérifiés ; pas d'extension du bundle par un chemin fourni dans la commande. Le monitor parental macOS n'est pas une garantie noyau inconditionnelle quand tout le processus est suspendu.

Les trois lanes commandes/préférences/consultation doivent rester bornés, avec admission/replay/CAS/pending et résultat explicite. Les nouveaux verbes impliquent un contrat strict commun Rust/Dart (version suivante si schéma incompatible), pas un fallback permissif ou `execute(command,args)`. La fraîcheur du collecteur et la vivacité du transport sont distinctes : history/doctor/settings peuvent réussir pendant une observation périmée, sans rétablir artificiellement une carte « sûre ».

Versions indépendantes à conserver : JSON CLI/historique schéma3, IPC Flutter B5 protocole5, protocole du helper natif AppKit4. Ne pas appliquer une évolution du bridge Flutter aux messages du helper natif sans revoir ce contrat séparé.

### Risques structurants, décisions de planification

1. **Restauration** : préserver les trois contrats natifs plutôt que fabriquer une abstraction « unmute » universelle. La libération Windows manuelle reste explicite unmute-all, avec confirmation ; la restauration automatique et les originaux Unix restent leurs journaux existants. Pas de refonte profonde des originaux manuels pendant l'étape1.
   Limite à ne pas masquer : sous Windows les originaux automatiques sont retenus dans le `NativeLockJournal` du processus garde ; le fichier Intent persiste token/génération/pending, pas les valeurs originales de chaque endpoint. Après perte de cet owner, le code refuse une restauration aveugle et annonce « originals unavailable » (`windows_protection.rs:51-63,801-805,862-868,1000-1038`). La mort de Flutter/tray et celle de la garde ne sont donc pas la même preuve. L'UI doit conserver cet état non résolu ; ne pas promettre récupération intégrale des originaux après crash de la garde sans nouveau contrat approuvé.
2. **Parité réelle** : accès à Win32/GTK/AppKit = secours, jamais une case Flutter P1 terminée. Garder les sources natives jusqu'à validation du remplacement, sans deux fenêtres concurrentes normales.
3. **Distribution atomique** : l'updater actuel/pair receipt et la garde MSI/ZIP ne couvrent pas un runtime Flutter complet. Étendre ensemble packaging, découverte de bundle, intégrité, update, rollback, uninstall, locks et UI version ; pas de migration partielle d'exécutables.
4. **État inconnu** : aucune absence d'endpoint ou refus d'autorisation ne doit devenir Disabled/safe/blocked. Autostart COM B5 corrige déjà cette confusion d'inspection ; garder ce correctif.
5. **Linux ARM64** : preuve actuelle = Ubuntu24.04 build/ELF, non plancher glibc2.35/Ubuntu22.04 ni bureau ARM physique. Résoudre la compatibilité ancienne baseline sans abaisser discrètement le support.
6. **macOS** : menu bar AppKit permanent, pinned SDK et Skia opt-out validés à conserver ; vieux JSON de préparation et documents protocole1/3 ne sont pas preuves de l'état actuel. Intel déprécié en amont n'est pas supprimé du projet ; requalifier tout changement SDK/engine.
7. **Performance** : l'ancienne0.21.1 native n'est pas un baseline Flutter ni une mesure de0.22. `watch` Windows appelle `resume_requested_microphone_protection` au démarrage, même avec `--no-kill` : ne pas qualifier cette commande de strictement passive ni la lancer sur l'installation quotidienne pour benchmarker. Les chemins de données privés ne garantissent pas une isolation de la ressource système/singleton.
8. **Identité/versions** : B5 Rust0.21.0, pubspec/About0.21.1 et IDs de développement ne sont pas les métadonnées d'un produit0.22 final. Aligner versions sans supprimer arbitrairement les IDs helper nécessaires à TCC/notifications.
