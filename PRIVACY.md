# Privacy Policy

**MicCamWatch** (`mcw`) is an open-source, offline-first security and privacy monitor for Windows, Linux and macOS. Controls have explicit platform scopes: Windows device administration, Linux PipeWire-session source mute and optional administrator-authorized USB webcam controls, and macOS writable INPUT mute/manual Restrictions profiles. None is advertised as a universal hardware kill-switch.

## Data Collection and Storage

- **Offline by default**: Monitoring sends no telemetry, analytics, crash reports or activity history. Explicit installation/update contacts GitHub for installer/release metadata, archives and checksums; observations and local policy are not uploaded. With `trust_policy = "offline"`, Windows forbids online chain/revocation retrieval, macOS uses Security.framework's no-network validation flag, and Linux disables GnuPG automatic key retrieval/import and WKD lookup. Explicit `"online"` permits native Windows/macOS certificate-revocation work, or Linux automatic key retrieval through GnuPG's keyserver configuration (including its defaults). These services can learn the requested certificate/key, IP and timing. macOS best-attempt revocation does not guarantee a fresh positive response; verification is not a Gatekeeper/notarization or antivirus verdict.
- **No Audio or Video Recording**: MicCamWatch never records audio streams, captures webcam frames, or inspects media payloads. It only reads OS-level metadata:
  - Windows Core Audio / WASAPI session information (PID, session state, capture device name).
  - Windows Capability Access Manager registry timestamps (`LastUsedTimeStart`, `LastUsedTimeStop`).
  - Windows Media Foundation sensor process-activity/streaming-state metadata; an active stream without a validated PID remains unattributed.
  - Loaded DLL modules associated with capture frameworks (DirectShow, Media Foundation) to correlate capability.
  - Process metadata (PID, executable path, process tree ancestry, Authenticode digital signatures) to identify which application accessed the device.
  - Linux PipeWire graph metadata, authenticated client/process identity, `/proc` metadata and V4L2 device inventory/open-handle observations.
  - macOS CoreAudio process input-activity metadata, AVFoundation device inventory, public CoreMediaIO camera device running-state and process identity from `libproc`. Camera client/PID stays unknown; running-state does not prove frame flow. The embedded native helper does not start a media capture session or request camera permission.
- **Local Storage**: By default, generated files are under your Windows user profile:
  - Settings: `%APPDATA%\MicCamWatch\settings.toml`
  - Activity history: `%LOCALAPPDATA%\MicCamWatch\history.jsonl` (and rotated files, when enabled)
  - Camera block state: `%LOCALAPPDATA%\MicCamWatch\blocked-camera-devices.json`
  - Optional `mcw watch --log` writes to the path you choose; `--eventlog` delivers local Windows Event Log, Linux syslog/journal, or macOS unified-log entries. OS logging retention/access rules are outside MCW's history settings.
- **Unix Local Storage and Installation**: Settings, policy, rotating history, private control-ownership journals, autostart receipts and local tray IPC metadata use the platform's per-user XDG/HOME locations. The installer defaults to `$HOME/.local/bin` and stores executable/PATH ownership receipts under that prefix. It never silently enables autostart, changes device state or edits TCC/Gatekeeper. It refuses replacement/removal of an active installed executable; stop its watcher/tray yourself first. Uninstallation preserves settings, policy, history and control-ownership data. Restore owned mute changes and remove an installed owned camera profile explicitly before removing MCW if desired.
- **Linux Administrator Camera State**: Optional USB webcam controls require a separately reviewed, matching root helper and explicit Polkit administrator authorization. `/var/lib/miccamwatch` stores a root-only restoration journal and installation receipt plus a locally readable status cache containing owned USB identities (boot, topology, descriptors and optional serial), authorizing caller UID, original driver bindings and operation state; no media or network upload. Actions target only admitted UVC video interfaces, not separate audio/storage interfaces, non-USB cameras or global driver modules. No automatic hotplug or camera-on-lock action is performed. Restore owned bindings and explicitly uninstall the root component before an ordinary user update/removal; install the new matching root component separately afterward. Removal refuses pending/malformed restoration evidence and preserves the permanent operation lock.
- **macOS Helper Identity**: Embedded public-framework code runs in a private, per-user helper `.app` with a stable application identifier. Local ad-hoc signing supports that application identity; it is not Apple Developer ID, notarization or a trusted publisher claim. Cleanup removes only owned helper material and preserves bundles still in use. Native notification authorization and manual camera-profile installation/removal remain user-controlled.
- **Scoped Privacy Controls**: Windows camera actions use the absolute system `pnputil` and require explicit administrator approval (UAC). Linux microphone changes affect only sources in the accessible PipeWire session, never global ALSA policy; optional USB camera actions use the separate root/Polkit component described above, never permission-only V4L2 denial. macOS changes only exposed writable INPUT CoreAudio mute properties. Owned restoration preserves previously muted sources and retains unavailable-device work for a later retry. A macOS camera restriction is a manually approved profile identified by an owned UUID; installed payload metadata is profile evidence, not physical capture-denial proof. External profiles are never removed. Public macOS lock state remains Unknown, and lock-policy enable is refused.
- **Local Background Monitoring**: Windows uses its windowless tray; Linux requires an actual StatusNotifier host and session notification service; macOS uses its native AppKit menu bar. These observe metadata and optionally retain history/deliver alerts. Windows lifecycle uses local window messages; Unix lifecycle uses private same-user local IPC. No remote tray service is used. Explicit autostart consent creates an owned per-user Windows registration, Linux desktop entry, or macOS LaunchAgent; updates never silently enable an absent/disabled/unmanaged registration.
